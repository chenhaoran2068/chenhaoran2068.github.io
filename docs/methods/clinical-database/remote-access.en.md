<header class="guide-header"><p class="guide-kind">Clinical Database · Access request</p><h1>Request remote read-only access</h1><div class="guide-intro"><p>You may build and maintain your own clinical database, or request read-only use of one maintained by an administrator.</p><p>This page covers the second case. Start here if you do not yet have an individual read-only account and connection material.</p><p>Tell the administrator the purpose, required data scope, device, and expected duration. Configure the client only after approval and delivery of the connection material.</p></div></header>

<section class="guide-section" id="before-request"><div class="section-header"><div><p class="section-context">Before requesting</p><h2>Confirm this information</h2></div><p>The request covers one person, one device, and a defined data scope. It is not unrestricted access to the database.</p></div><ul class="database-checklist"><li>Which database is needed and which schemas or sources are required.</li><li>Which Study or task needs remote queries and why.</li><li>Whether the necessary data-use permission already exists.</li><li>Which Windows or macOS computer will be used.</li><li>The expected start and end dates.</li><li>Whether DBeaver, psql, or both will be used.</li></ul><h3 class="database-subheading">How far the device can be prepared in advance</h3><div class="access-preparation-steps"><article><span>Before applying</span><div><h4>Record the device and intended use</h4><p>You may install Tailscale, DBeaver Community, or psql. Record the operating system, device name, intended Tailscale sign-in identity, and client choice. Do not configure a database connection yet.</p></div></article><article><span>After invitation</span><div><h4>Confirm the Tailscale device identity</h4><p>Sign in after the administrator invites you to the approved Tailscale network. If device approval is enabled, wait for the administrator to approve the device. Once it appears in the approved network, provide the device name and Tailscale IPv4 when requested.</p></div></article></div><div class="command-pair device-check-commands"><article><h4>Windows PowerShell</h4><pre data-copy data-copy-label="Copy commands" data-copied-label="Copied"><code>hostname
tailscale version
tailscale status
tailscale ip -4</code></pre></article><article><h4>macOS Terminal</h4><pre data-copy data-copy-label="Copy commands" data-copied-label="Copied"><code>scutil --get ComputerName
tailscale version
tailscale status
tailscale ip -4</code></pre></article></div><div class="db-notice"><strong>Do not provide an ordinary network IP</strong><p>Do not send a Wi-Fi LAN or public IP. This method normally uses the device name, operating system, Tailscale sign-in identity, and, when requested, the single address returned by <code>tailscale ip -4</code>.</p></div><div class="db-notice"><strong>The validated implementation uses the Tailscale IPv4</strong><p>IMP-DB-002 narrowed the server firewall allowlist to the approved client's Tailscale IPv4. Provide this address after the device joins the approved network; an ordinary network IP is not needed.</p></div><div class="db-notice"><strong>Use <code>tailscale status</code> for your own check</strong><p>Confirm that the device is online. Do not paste the full output into the request by default because it may list other devices. During troubleshooting, send only the fields the administrator requests.</p></div><p class="database-source-note">The network administrator controls device approval and access rules. See <a href="https://tailscale.com/docs/features/access-control/device-management/device-approval">Tailscale Device approval</a> and the <a href="https://tailscale.com/docs/reference/tailscale-cli">Tailscale CLI reference</a>.</p><div class="db-notice db-notice-warning"><strong>Do not include secrets or patient data</strong><p>Do not send passwords, private keys, patient records, or credential files. Each person requests an individual account and does not borrow another person's account.</p></div></section>

<section class="guide-section" id="request-template"><div class="section-header"><div><p class="section-context">Send to the administrator</p><h2>Copy and complete this request</h2></div><p>Replace text in angle brackets. Write “not applicable” where appropriate.</p></div><pre data-copy><code>I request remote read-only access to the Clinical Database.

Applicant: &lt;name&gt;
Team: &lt;team or research group&gt;
Contact: &lt;administrator-approved contact channel&gt;
Research or work purpose: &lt;purpose&gt;
Data-use permission: &lt;existing permission or status to be checked&gt;
Database requested: &lt;database name&gt;
Schemas or sources requested: &lt;minimum necessary scope&gt;
Device: &lt;Windows or macOS; use the device identifier requested by the administrator&gt;
Device name: &lt;hostname or ComputerName&gt;
Tailscale sign-in identity: &lt;account used to join the approved network&gt;
Tailscale IPv4: &lt;provide after the device is approved; write “pending assignment” before joining&gt;
Expected access period: &lt;start date to end date&gt;
Planned client: &lt;DBeaver, psql, or both&gt;

Please tell me what else is required and whether this request is approved, needs more information, is deferred, or cannot be approved.</code></pre><p class="database-source-note">Send it through the administrator's designated channel. Public pages, Git, screenshots, and shared scripts are not suitable for passwords or credentials.</p></section>

<section class="guide-section" id="outcomes"><div class="section-header"><div><p class="section-context">Administrator reply</p><h2>Possible request states</h2></div><p>“More information” and “deferred” are not approvals and are not mandatory intermediate steps.</p></div><div class="permission-layers"><article><span>Approved</span><div><h3>Prepare individual read-only access</h3><p>The administrator creates an individual account, limits schemas and duration, and prepares the Tailscale and TLS connection material.</p></div></article><article><span>More information</span><div><h3>The request is incomplete</h3><p>Supply the identified gap in purpose, permission, device, or access scope, then ask for review again.</p></div></article><article><span>Deferred</span><div><h3>A required condition is not ready</h3><p>The server, approval, certificate, or source permission is not ready. Keep the request and resume when the condition is met.</p></div></article><article><span>Declined</span><div><h3>The current request cannot be approved</h3><p>The administrator explains the reason and possible alternatives. Do not bypass the decision by disabling TLS, opening a public port, or sharing an account.</p></div></article></div></section>

<section class="guide-section" id="after-approval"><div class="section-header"><div><p class="section-context">After approval</p><h2>Configure only after receiving the complete package</h2></div><p>The administrator maintains the server, account, certificate, and authorization scope. The researcher configures only the approved client computer.</p></div><div class="evidence-split"><div><h3>Administrator delivers securely</h3><p>MagicDNS name, port, database name, individual username, root CA, approved schemas, and access period. The password is delivered through a separate secure channel.</p></div><div><h3>Researcher configures and verifies</h3><p>Install and sign in to the approved Tailscale network, store the root CA, configure DBeaver or psql, then verify TLS, account, schema, and read-only permissions.</p></div></div><div class="db-notice db-notice-warning"><strong>Approval is not permanent access</strong><p>When the period ends, a device is lost, a person leaves, or the permitted scope changes, contact the administrator to revoke the Tailscale device and database account.</p></div><div class="guide-next-links"><a href="../client-setup/"><strong>Configure and verify the client</strong><span>Windows, macOS, DBeaver, psql, and read-only verification</span></a><a href="../troubleshooting/"><strong>Troubleshooting and safety</strong><span>When the network, TLS, authentication, or permissions fail</span></a></div></section>
