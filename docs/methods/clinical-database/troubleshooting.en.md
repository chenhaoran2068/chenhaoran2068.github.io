<header class="guide-header"><p class="guide-kind">Clinical Database · troubleshooting and safety</p><h1>Find the layer where the connection fails</h1><p>Do not change many settings at once. Check device, Tailscale, name resolution, port, TLS, authentication, and database authorization in order, then hand the issue to the correct owner.</p></header>
<nav class="database-guide-nav"><a href="#diagnostic-order">Order</a><a href="#problems">Problems</a><a href="#permissions">Read-only</a><a href="#security">Safety</a><a href="#operations">Operations</a></nav>
<section class="guide-section" id="diagnostic-order"><div class="section-header"><div><p class="section-context">Find the owner</p><h2>Six diagnostic layers</h2></div></div><div class="diagnostic-strip"><span>Device online</span><i>→</i><span>Approved tailnet</span><i>→</i><span>MagicDNS</span><i>→</i><span>Port reachable</span><i>→</i><span>TLS and authentication</span><i>→</i><span>Schema and table privileges</span></div><div class="db-notice"><strong>Record the symptom without publishing raw output</strong><p>Logs can expose device, account, address, and path identifiers. De-identify them before sharing beyond the approved support channel.</p></div></section>
<section class="guide-section" id="problems"><div class="section-header"><div><p class="section-context">Open by symptom</p><h2>Common problems</h2></div><p>Each item states what it means, likely causes, owner, action, and unsafe workaround.</p></div><div class="troubleshooting-details">
<details><summary>Tailscale device offline or awaiting approval</summary><div><p><strong>Meaning:</strong> client or server is not communicating in the approved tailnet.</p><p><strong>Causes:</strong> power, sign-in, wrong account, expired authorization, or pending device approval.</p><p><strong>Owner:</strong> researcher checks the client; administrator checks server and approval.</p><p><strong>Action:</strong> run <code>tailscale status</code> and verify sign-in and approval.</p><p><strong>Do not:</strong> use a public address or another person's device identity.</p></div></details>
<details><summary>MagicDNS does not resolve</summary><div><p><strong>Meaning:</strong> the MagicDNS host cannot be resolved inside the tailnet.</p><p><strong>Causes:</strong> spelling, disabled MagicDNS, client DNS state, or wrong tailnet.</p><p><strong>Owner:</strong> researcher checks the delivered name; administrator checks MagicDNS.</p><p><strong>Action:</strong> use <code>tailscale ping &lt;server-magicdns-name&gt;</code>.</p><p><strong>Do not:</strong> substitute an IP that is absent from the certificate SAN.</p></div></details>
<details><summary>connection timeout</summary><div><p><strong>Meaning:</strong> no PostgreSQL session was established in time.</p><p><strong>Causes:</strong> the server or PostgreSQL is offline, the Tailscale path is unavailable, or network policy denies the connection.</p><p><strong>Owner:</strong> the researcher checks device connectivity; the administrator checks the server and network policy.</p><p><strong>Action:</strong> verify Tailscale, MagicDNS, and server state in that order.</p><p><strong>Do not:</strong> extend timeouts indefinitely or expose a public port.</p></div></details>
<details><summary>Wrong port</summary><div><p><strong>Meaning:</strong> the hostname resolves, but the client is trying a port other than the delivered PostgreSQL port.</p><p><strong>Causes:</strong> a copied default, an old profile, or a typing error.</p><p><strong>Owner:</strong> the researcher checks the connection profile; the administrator confirms the current port.</p><p><strong>Action:</strong> compare the DBeaver or psql value with the administrator's handoff and correct only that field.</p><p><strong>Do not:</strong> scan nearby ports or guess a replacement.</p></div></details>
<details><summary>certificate verify failed</summary><div><p><strong>Meaning:</strong> the selected root CA cannot validate the server chain.</p><p><strong>Causes:</strong> wrong or damaged CA, expiry, or connection to the wrong service.</p><p><strong>Owner:</strong> researcher checks the CA; administrator checks chain and expiry.</p><p><strong>Action:</strong> confirm CA source, fingerprint, validity, and destination.</p><p><strong>Do not:</strong> disable verification or change to <code>require</code>.</p></div></details>
<details><summary>Hostname does not match certificate SAN</summary><div><p><strong>Meaning:</strong> Host is not a name authorized by the server certificate.</p><p><strong>Causes:</strong> short name, IP, old MagicDNS name, or missing SAN.</p><p><strong>Owner:</strong> researcher uses the delivered host; administrator reissues the server certificate if needed.</p><p><strong>Action:</strong> keep <code>verify-full</code> and make Host match the SAN.</p><p><strong>Do not:</strong> skip hostname validation.</p></div></details>
<details><summary>password authentication failed</summary><div><p><strong>Meaning:</strong> the server did not accept account authentication.</p><p><strong>Causes:</strong> username/password, expired or revoked account, wrong database, or unsupported SCRAM client.</p><p><strong>Owner:</strong> researcher re-enters credentials; administrator checks account state.</p><p><strong>Action:</strong> verify username, database, expiry, and client version.</p><p><strong>Do not:</strong> send the password in tickets, commands, files, or screenshots.</p></div></details>
<details><summary>Schema visible but tables cannot be queried</summary><div><p><strong>Meaning:</strong> visibility does not imply schema USAGE and table SELECT.</p><p><strong>Causes:</strong> one privilege missing, a new table not approved, or schema outside allowlist.</p><p><strong>Owner:</strong> administrator checks the approved grant; researcher does not self-escalate.</p><p><strong>Action:</strong> use <code>has_schema_privilege</code> and <code>has_table_privilege</code>.</p><p><strong>Do not:</strong> request wildcard access to governance, registry, or unapproved sources.</p></div></details>
<details><summary>DBeaver driver is missing</summary><div><p><strong>Meaning:</strong> no PostgreSQL JDBC driver is available.</p><p><strong>Causes:</strong> first use, proxy/network restriction, or damaged cache.</p><p><strong>Owner:</strong> client support or researcher, not database authorization.</p><p><strong>Action:</strong> use DBeaver Driver Manager and an official source.</p><p><strong>Do not:</strong> download drivers from unknown sites.</p></div></details>
<details><summary>Server or PostgreSQL is offline</summary><div><p><strong>Meaning:</strong> no database service can answer.</p><p><strong>Causes:</strong> planned maintenance, fault, or power loss.</p><p><strong>Owner:</strong> server administrator.</p><p><strong>Action:</strong> confirm the maintenance window and recovery time.</p><p><strong>Do not:</strong> repeatedly change client certificates and passwords.</p></div></details>
<details><summary>Access expired, paused, or revoked</summary><div><p><strong>Meaning:</strong> a formerly valid device or account no longer has current authorization.</p><p><strong>Causes:</strong> expiry, device loss, role/project change, or incomplete review.</p><p><strong>Owner:</strong> data owner and administrator.</p><p><strong>Action:</strong> reapply for the current scope or complete the review.</p><p><strong>Do not:</strong> use another person's active account.</p></div></details>
</div></section>
<section class="guide-section" id="permissions"><div class="section-header"><div><p class="section-context">Not one switch</p><h2>Read-only must hold at every layer</h2></div></div><div class="permission-layers"><article><span>01</span><div><h3>Connect</h3><p>Tailscale, TLS, database CONNECT, and authentication succeed.</p></div></article><article><span>02</span><div><h3>Use a schema</h3><p>USAGE exists only for allowlisted schemas.</p></div></article><article><span>03</span><div><h3>Query approved tables</h3><p>SELECT exists only for explicit objects. New schemas do not inherit approval.</p></div></article><article><span>04</span><div><h3>No write or escalation</h3><p>No CREATE, INSERT, UPDATE, DELETE, TRUNCATE, superuser, database creation, role creation, or replication.</p></div></article></div></section>
<section class="guide-section" id="security"><div class="section-header"><div><p class="section-context">Must remain true</p><h2>Safety rules</h2></div></div><div class="security-columns"><div><h3>Network and identity</h3><ul><li>Never expose PostgreSQL directly to the public internet.</li><li>Use one account per person.</li><li>On device loss, revoke both Tailscale and database access.</li></ul></div><div><h3>Password and certificates</h3><ul><li>No password in scripts, pages, screenshots, or Git.</li><li>The root CA certificate may be distributed; its private key may not.</li><li>The server private key remains on the server.</li></ul></div><div><h3>Minimum scope</h3><ul><li>Approve only needed schemas and tables.</li><li>No governance, registry, or unapproved sources.</li><li>New schemas require explicit review.</li></ul></div></div></section>
<section class="guide-section" id="operations"><div class="section-header"><div><p class="section-context">Routine use</p><h2>Quick checklist</h2></div></div><ul class="quick-check"><li>Client and server are online in the approved tailnet.</li><li>Host is the MagicDNS name in the certificate SAN.</li><li>TLS remains <code>verify-full</code>.</li><li>The account is individual and no password is stored in public material.</li><li>Queries remain inside approved schemas and tables.</li><li>Account scope, expiry, source allowlist, and certificate expiry are reviewed.</li><li>New committed server data appears in new queries; no database copy is needed.</li><li>DBeaver is installed only on clients that need a GUI.</li></ul><h3 class="sources-heading">Official sources</h3><ul class="official-sources"><li><a href="https://www.postgresql.org/docs/current/libpq-connect.html">PostgreSQL: connection parameters</a></li><li><a href="https://www.postgresql.org/docs/current/libpq-ssl.html">PostgreSQL: SSL support</a></li><li><a href="https://www.postgresql.org/docs/current/auth-password.html">PostgreSQL: password authentication</a></li><li><a href="https://tailscale.com/kb/1081/magicdns">Tailscale: MagicDNS</a></li><li><a href="https://dbeaver.com/docs/dbeaver/SSL-Configuration/">DBeaver: SSL configuration</a></li></ul></section>
