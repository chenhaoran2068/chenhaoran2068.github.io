<section class="guide-section" id="diagnostic-order"><div class="section-header"><div><p class="section-context">先判断谁来处理</p><h2>六层检查顺序</h2></div><p>前一层不通时，不继续修改后一层。</p></div><div class="diagnostic-strip"><span>设备在线</span><i>→</i><span>同一获准 tailnet</span><i>→</i><span>MagicDNS 解析</span><i>→</i><span>端口可达</span><i>→</i><span>TLS 与认证</span><i>→</i><span>schema 与表权限</span></div><div class="db-notice"><strong>先记录现象，不公开原始输出</strong><p>告诉管理员错误发生在哪个客户端、哪一层和大致时间。截图或日志中可能有设备名、账户名、地址和路径，公开前应去标识化。</p></div></section>

<section class="guide-section" id="problems"><div class="section-header"><div><p class="section-context">按现象打开</p><h2>常见问题</h2></div><p>每项都说明含义、常见原因、负责人和不能采用的绕过办法。</p></div><div class="troubleshooting-details">
<details><summary>Tailscale 设备离线或等待批准</summary><div><p><strong>是什么意思：</strong>客户端或服务器没有处在可通信的获准 tailnet 状态。</p><p><strong>常见原因：</strong>设备关机、未登录、登录了错误账户、设备授权过期，或仍在等待管理员批准。</p><p><strong>谁处理：</strong>研究人员确认自己的客户端；管理员确认服务器和设备批准状态。</p><p><strong>怎样做：</strong>运行 <code>tailscale status</code>，核对登录状态和设备审批。</p><p><strong>不要：</strong>改用公网地址或共享他人设备身份。</p></div></details>
<details><summary>MagicDNS 无法解析</summary><div><p><strong>是什么意思：</strong><code>&lt;server-magicdns-name&gt;</code> 不能被转换为 tailnet 内地址。</p><p><strong>常见原因：</strong>名称拼写错误、MagicDNS 未启用、客户端 DNS 状态异常或不在正确 tailnet。</p><p><strong>谁处理：</strong>研究人员先核对名称；管理员核对 MagicDNS 与 tailnet 配置。</p><p><strong>怎样做：</strong>使用 <code>tailscale ping &lt;server-magicdns-name&gt;</code>，并对照管理员交付的完整名称。</p><p><strong>不要：</strong>随意改成 IP；IP 不在证书 SAN 时会导致 <code>verify-full</code> 失败。</p></div></details>
<details><summary>connection timeout</summary><div><p><strong>是什么意思：</strong>客户端在规定时间内没有建立 PostgreSQL 连接。</p><p><strong>常见原因：</strong>服务器或 PostgreSQL 停止、Tailscale 不通、端口错误、访问策略未放行。</p><p><strong>谁处理：</strong>研究人员核对交付值；管理员检查服务和网络策略。</p><p><strong>怎样做：</strong>依次检查 Tailscale、MagicDNS、服务器在线状态和端口。</p><p><strong>不要：</strong>无限延长超时或开放公网端口。</p></div></details>
<details><summary>端口配置错误</summary><div><p><strong>是什么意思：</strong>客户端连接的不是管理员指定的 PostgreSQL 监听端口。</p><p><strong>常见原因：</strong>猜用了默认端口、复制了旧环境值，或把网页端口当成数据库端口。</p><p><strong>谁处理：</strong>研究人员对照交付包；管理员确认当前监听值。</p><p><strong>怎样做：</strong>只使用 <code>&lt;postgresql-port&gt;</code> 的正式交付值。</p><p><strong>不要：</strong>逐个扫描端口。</p></div></details>
<details><summary>certificate verify failed</summary><div><p><strong>是什么意思：</strong>客户端不能用指定根 CA 验证服务器证书链。</p><p><strong>常见原因：</strong>选错 CA、文件损坏、证书过期，或连到了错误服务。</p><p><strong>谁处理：</strong>研究人员核对 CA 文件；管理员核对证书链和到期时间。</p><p><strong>怎样做：</strong>重新核对 CA 来源、指纹、有效期和连接目标。</p><p><strong>不要：</strong>关闭 TLS 验证、接受任意证书或改成 <code>require</code>。</p></div></details>
<details><summary>主机名与证书 SAN 不匹配</summary><div><p><strong>是什么意思：</strong>Host 字段不是服务器证书明确允许的名称。</p><p><strong>常见原因：</strong>用了短名称、IP、旧 MagicDNS 名称，或服务器证书漏签当前名称。</p><p><strong>谁处理：</strong>研究人员使用正式主机名；缺少 SAN 时由管理员重签服务器证书。</p><p><strong>怎样做：</strong>保持 <code>verify-full</code>，让 Host 与 SAN 完全匹配。</p><p><strong>不要：</strong>勾选“Skip host name validation”。</p></div></details>
<details><summary>password authentication failed</summary><div><p><strong>是什么意思：</strong>服务器没有接受该账户的认证。</p><p><strong>常见原因：</strong>用户名或密码错误、账户过期/锁定/撤销、连错数据库，或客户端没有满足 SCRAM 要求。</p><p><strong>谁处理：</strong>研究人员重新输入而不公开密码；管理员检查账户状态。</p><p><strong>怎样做：</strong>核对用户名、数据库、账户期限和受支持的客户端版本。</p><p><strong>不要：</strong>在工单、命令、环境文件或截图中发送密码。</p></div></details>
<details><summary>schema 看得见但不能查询</summary><div><p><strong>是什么意思：</strong>能列出名称不等于同时拥有 schema USAGE 和表 SELECT。</p><p><strong>常见原因：</strong>只授予其中一层、新表没有按批准规则授权，或该 schema 不在 allowlist。</p><p><strong>谁处理：</strong>管理员按批准范围核对授权；研究人员不能自行扩权。</p><p><strong>怎样做：</strong>运行 <code>has_schema_privilege</code> 与 <code>has_table_privilege</code> 的无患者值检查。</p><p><strong>不要：</strong>要求整个数据库、governance、registry 或未批准来源的通配权限。</p></div></details>
<details><summary>DBeaver 驱动未下载</summary><div><p><strong>是什么意思：</strong>DBeaver 还没有可用的 PostgreSQL JDBC 驱动。</p><p><strong>常见原因：</strong>首次连接、客户端网络或代理限制、驱动缓存损坏。</p><p><strong>谁处理：</strong>客户端支持人员或研究人员；不是数据库权限问题。</p><p><strong>怎样做：</strong>通过 DBeaver 驱动管理器从正式来源下载，必要时核对代理。</p><p><strong>不要：</strong>从不明网站下载驱动包。</p></div></details>
<details><summary>服务器关机或 PostgreSQL 服务停止</summary><div><p><strong>是什么意思：</strong>远端没有可响应的数据库服务。</p><p><strong>常见原因：</strong>计划停机、故障、维护或本机断电。</p><p><strong>谁处理：</strong>服务器管理员。</p><p><strong>怎样做：</strong>确认维护窗口与恢复时间。客户端不需要重建数据库副本。</p><p><strong>不要：</strong>在客户端反复修改证书和密码。</p></div></details>
<details><summary>访问期限到期、暂停或撤销</summary><div><p><strong>是什么意思：</strong>曾经可用的设备或账户不再具有当前授权。</p><p><strong>常见原因：</strong>批准期限结束、设备丢失、人员或项目变更、定期复核未完成。</p><p><strong>谁处理：</strong>数据责任人和管理员。</p><p><strong>怎样做：</strong>按新范围重新申请或完成复核；保留撤销记录。</p><p><strong>不要：</strong>改用仍有效的他人账户。</p></div></details>

<section class="guide-section" id="permissions"><div class="section-header"><div><p class="section-context">权限不是一个开关</p><h2>“只读”需要逐层成立</h2></div></div><div class="permission-layers"><article><span>01</span><div><h3>能连接</h3><p>Tailscale、TLS、数据库 CONNECT 和账户认证都通过。</p></div></article><article><span>02</span><div><h3>能使用 schema</h3><p>只对 allowlist 中的 schema 有 USAGE；能看到名称不代表有 USAGE。</p></div></article><article><span>03</span><div><h3>能查询批准的表</h3><p>只有明确授权对象具备 SELECT。新增 schema 和来源不会自动进入范围。</p></div></article><article><span>04</span><div><h3>不能写入或扩权</h3><p>不能 CREATE、INSERT、UPDATE、DELETE、TRUNCATE；不能成为超级用户、建库、建角色或取得复制权限。</p></div></article></div></section>

<section class="guide-section" id="security"><div class="section-header"><div><p class="section-context">必须保持</p><h2>安全要求</h2></div></div><div class="security-columns"><div><h3>网络与身份</h3><ul><li>PostgreSQL 端口不直接暴露到公网。</li><li>每人使用独立账户，不共享账户。</li><li>丢失设备时同时撤销 Tailscale 设备和数据库账户。</li></ul></div><div><h3>密码与证书</h3><ul><li>密码不写入脚本、网页、截图或 Git。</li><li>根 CA 证书可以分发，根 CA 私钥绝不分发。</li><li>服务器证书私钥只留在服务器。</li></ul></div><div><h3>最小授权</h3><ul><li>只批准需要的 schema 和表。</li><li>不能访问 governance、registry 或未批准来源。</li><li>新增 schema 必须显式审查，不自动扩大范围。</li></ul></div></div></section>

<section class="guide-section" id="operations"><div class="section-header"><div><p class="section-context">日常使用</p><h2>运维说明与快速检查清单</h2></div></div><ul class="quick-check"><li>客户端和服务器都在线，并在同一获准 tailnet。</li><li>Host 使用证书 SAN 中的 MagicDNS 名称。</li><li>TLS 保持 <code>verify-full</code>，根 CA 来源已核对。</li><li>用户名属于本人，密码没有写进任何文件或截图。</li><li>只查询批准的 schema 与表。</li><li>账户期限、来源 allowlist 和证书到期日在复核范围内。</li><li>本机数据提交后，新的远端查询会看到最新已提交状态；不复制数据库。</li><li>DBeaver 只装在需要图形查询的客户端，服务器无需安装。</li></ul><h3 class="sources-heading">官方资料</h3><ul class="official-sources"><li><a href="https://www.postgresql.org/docs/current/libpq-connect.html">PostgreSQL: connection parameters</a></li><li><a href="https://www.postgresql.org/docs/current/libpq-ssl.html">PostgreSQL: SSL support</a></li><li><a href="https://www.postgresql.org/docs/current/auth-password.html">PostgreSQL: password authentication</a></li><li><a href="https://tailscale.com/kb/1081/magicdns">Tailscale: MagicDNS</a></li><li><a href="https://tailscale.com/kb/1019/subnets">Tailscale: connectivity concepts</a></li><li><a href="https://dbeaver.com/docs/dbeaver/SSL-Configuration/">DBeaver: SSL configuration</a></li></ul></section>
