<header class="guide-header"><p class="guide-kind">Clinical Database · 客户端</p><h1>配置并验证远端只读客户端</h1><p>适用于访问申请已经批准，管理员也已交付连接信息的情况。Windows 与 macOS 都通过 Tailscale 私有网络访问同一套 PostgreSQL；客户端不保存数据库副本。</p></header>

<section class="guide-section" id="handoff-package"><div class="section-header"><div><p class="section-context">开始条件</p><h2>先核对管理员交付的资料</h2></div><p>缺少任何一项，回到<a href="../remote-access/">访问申请</a>补齐，不要猜测或降低验证要求。</p></div><ul class="database-checklist"><li>服务器 MagicDNS 名称 <code>&lt;server-magicdns-name&gt;</code>。</li><li>PostgreSQL 端口 <code>&lt;postgresql-port&gt;</code>。</li><li>数据库名称 <code>&lt;database-name&gt;</code>。</li><li>你的独立只读用户名 <code>&lt;read-only-user&gt;</code>；密码通过安全渠道单独获得。</li><li>允许访问的 schema，以及一张获准用于权限验证的表。</li><li>可分发的根 CA 证书 <code>root-ca.crt</code>，不是任何私钥。</li><li>管理员确认服务器证书 SAN 包含将要使用的 MagicDNS 名称。</li></ul><div class="db-notice db-notice-warning"><strong>不要接收私钥</strong><p>根 CA 公开证书可以交付给客户端；根 CA 私钥和服务器证书私钥只能留在服务器端。</p></div></section>

<section class="guide-section" id="architecture"><div class="section-header"><div><p class="section-context">连接链路</p><h2>数据怎样到达你的查询窗口</h2></div><p>Tailscale 控制网络可达性；PostgreSQL TLS 再验证服务器身份并加密会话。</p></div><div class="database-access-flow"><article><span>01</span><div><h3>Windows 或 macOS</h3><p>使用 DBeaver 或 psql，持有根 CA 公开证书。</p></div></article><div class="database-flow-arrow" aria-hidden="true">↓</div><article><span>02</span><div><h3>Tailscale 私有网络</h3><p>客户端和服务器位于同一个获准的 tailnet；不要求处于同一 Wi-Fi。</p></div></article><div class="database-flow-arrow" aria-hidden="true">↓</div><article><span>03</span><div><h3>MagicDNS 与 TLS <code>verify-full</code></h3><p>连接名称必须匹配服务器证书 SAN，同时验证证书链与主机名。</p></div></article><div class="database-flow-arrow" aria-hidden="true">↓</div><article><span>04</span><div><h3>SCRAM 与个人只读账户</h3><p>只查询明确授权的 schema 和表，不能写入或扩大权限。</p></div></article></div><div class="db-notice"><strong>服务器上的最新已提交数据会直接出现</strong><p>客户端每次查询服务器，不需要同步数据库文件。服务器离线、PostgreSQL 停止或 Tailscale 不可达时，远端也无法使用。</p></div></section>

<section class="guide-section" id="dbeaver"><div class="section-header"><div><p class="section-context">图形客户端</p><h2>DBeaver 通用配置</h2></div><p>先填 Main，再到 SSL 页设置证书。</p></div><div class="database-table-wrap"><table class="database-config-table"><thead><tr><th>项目</th><th>填写内容</th><th>注意</th></tr></thead><tbody><tr><td>Host</td><td><code>&lt;server-magicdns-name&gt;</code></td><td>必须与服务器证书 SAN 一致；不要加 <code>https://</code>。</td></tr><tr><td>Port</td><td><code>&lt;postgresql-port&gt;</code></td><td>使用管理员给出的端口。</td></tr><tr><td>Database</td><td><code>&lt;database-name&gt;</code></td><td>只连接获准数据库。</td></tr><tr><td>Username</td><td><code>&lt;read-only-user&gt;</code></td><td>使用自己的独立账户。</td></tr><tr><td>Password</td><td>连接时输入</td><td>不写入网页、脚本、截图或 Git。</td></tr><tr><td>SSL mode</td><td><code>verify-full</code></td><td>同时验证 CA 和主机名。</td></tr><tr><td>Root certificate</td><td><code>&lt;path-to-root-ca.crt&gt;</code></td><td>管理员交付的根 CA。</td></tr><tr><td>Client certificate / key</td><td>留空</td><td>未来启用 mTLS 前不要填写。</td></tr><tr><td>Skip host name validation</td><td>不勾选</td><td>不能绕过主机名验证。</td></tr></tbody></table></div><ol class="database-actions"><li>新建 PostgreSQL 连接并填写 Host、Port、Database 和 Username。</li><li>在 SSL 设置中选择 <code>verify-full</code>，指定 Root certificate。</li><li>Client certificate 与 Client key 留空。</li><li>点击 <strong>Test Connection</strong>；成功后先运行验证 SQL，不要立刻浏览患者记录。</li></ol><div class="db-notice db-notice-warning"><strong>不要改成 <code>require</code></strong><p><code>require</code> 只要求加密，不执行同等级的主机名验证。证书失败时应修正 CA、MagicDNS 或 SAN。</p></div></section>

<section class="guide-section" id="psql"><div class="section-header"><div><p class="section-context">命令行客户端</p><h2>使用 psql</h2></div><p>命令不保存密码，psql 会交互式询问。</p></div><div class="command-pair"><article><h3>Windows PowerShell</h3><p>从 <a href="https://www.postgresql.org/download/windows/">PostgreSQL 官方 Windows 下载页</a>取得 psql。</p><pre data-copy><code>$env:PGHOST = '&lt;server-magicdns-name&gt;'&#10;$env:PGPORT = '&lt;postgresql-port&gt;'&#10;$env:PGDATABASE = '&lt;database-name&gt;'&#10;$env:PGUSER = '&lt;read-only-user&gt;'&#10;$env:PGSSLMODE = 'verify-full'&#10;$env:PGSSLROOTCERT = (Join-Path $HOME 'DatabaseAccess\root-ca.crt')&#10;$env:PGCONNECT_TIMEOUT = '10'&#10;$env:PGREQUIREAUTH = 'scram-sha-256'&#10;$env:PGCHANNELBINDING = 'require'&#10;psql -W</code></pre></article><article><h3>macOS shell</h3><p><a href="https://www.postgresql.org/download/macosx/">PostgreSQL 官方 macOS 页面</a>列有 Homebrew 安装方法。</p><pre data-copy><code>brew install libpq&#10;export PGHOST='&lt;server-magicdns-name&gt;'&#10;export PGPORT='&lt;postgresql-port&gt;'&#10;export PGDATABASE='&lt;database-name&gt;'&#10;export PGUSER='&lt;read-only-user&gt;'&#10;export PGSSLMODE='verify-full'&#10;export PGSSLROOTCERT="$HOME/Library/Application Support/DatabaseAccess/root-ca.crt"&#10;export PGCONNECT_TIMEOUT='10'&#10;export PGREQUIREAUTH='scram-sha-256'&#10;export PGCHANNELBINDING='require'&#10;"$(brew --prefix libpq)/bin/psql" -W</code></pre></article></div><div class="db-notice"><strong>客户端不认识参数时先升级</strong><p>若 psql 不支持 <code>require_auth</code> 或 channel binding，安装较新的受支持客户端，不要静默删掉要求继续。</p></div></section>

<section class="guide-section" id="validation"><div class="section-header"><div><p class="section-context">连接后先做</p><h2>不读取患者值的验证</h2></div><p>先确认会话、TLS 和权限，再执行获准查询。</p></div><h3>会话与 TLS</h3><pre data-copy><code>SELECT current_database(), current_user,&#10;       current_setting('transaction_read_only') AS transaction_read_only;&#10;&#10;SELECT ssl, version, cipher&#10;FROM pg_stat_ssl&#10;WHERE pid = pg_backend_pid();</code></pre><h3>schema 与表权限</h3><pre data-copy><code>SELECT&#10;  has_schema_privilege(current_user, '&lt;approved-schema&gt;', 'USAGE') AS schema_usage,&#10;  has_schema_privilege(current_user, '&lt;approved-schema&gt;', 'CREATE') AS schema_create;&#10;&#10;SELECT&#10;  has_table_privilege(current_user, '&lt;approved-schema&gt;.&lt;approved-table&gt;', 'SELECT') AS can_select,&#10;  has_table_privilege(current_user, '&lt;approved-schema&gt;.&lt;approved-table&gt;', 'INSERT') AS can_insert,&#10;  has_table_privilege(current_user, '&lt;approved-schema&gt;.&lt;approved-table&gt;', 'UPDATE') AS can_update,&#10;  has_table_privilege(current_user, '&lt;approved-schema&gt;.&lt;approved-table&gt;', 'DELETE') AS can_delete,&#10;  has_table_privilege(current_user, '&lt;approved-schema&gt;.&lt;approved-table&gt;', 'TRUNCATE') AS can_truncate;</code></pre><h3>预期失败的写入探针</h3><div class="db-notice db-notice-warning"><strong>只使用管理员预先批准的对象名</strong><p>先确认对象不存在，并在 <code>BEGIN READ ONLY</code> 中运行。不要使用 TEMP 表，因为 PostgreSQL 允许只读事务操作临时表。</p></div><pre data-copy><code>SELECT to_regclass('&lt;approved-schema&gt;.&lt;approved-write-probe&gt;') IS NULL AS safe_to_test;&#10;BEGIN READ ONLY;&#10;CREATE TABLE &lt;approved-schema&gt;.&lt;approved-write-probe&gt; (probe_id integer);&#10;ROLLBACK;&#10;SELECT to_regclass('&lt;approved-schema&gt;.&lt;approved-write-probe&gt;') IS NULL AS probe_absent;</code></pre><div class="success-criteria"><h3>连接成功判定标准</h3><ul><li>MagicDNS 名称可达，<code>verify-full</code> 未降级。</li><li>服务器完成 SCRAM；支持时完成 channel binding。</li><li><code>current_database()</code> 与 <code>current_user</code> 正确，<code>transaction_read_only</code> 为 <code>on</code>。</li><li><code>pg_stat_ssl</code> 显示 SSL 已启用。</li><li>只对批准 schema 有 USAGE，只对批准表有 SELECT。</li><li>CREATE、INSERT、UPDATE、DELETE、TRUNCATE 不可用。</li><li>写入探针失败，且 <code>probe_absent</code> 为 <code>true</code>。</li></ul></div></section>
