<section class="component-category-section component-facts" aria-labelledby="framework-role-title">
  <div class="component-category-section-heading">
    <p class="map-kicker">CATEGORY ROLE</p>
    <h2 id="framework-role-title">负责什么，不负责什么</h2>
  </div>
  <dl>
    <div>
      <dt>定义</dt>
      <dd>工作区根目录、System 注册、项目绑定与多 System 隔离边界。</dd>
    </div>
    <div>
      <dt>进入时机</dt>
      <dd>建立、扩展或审核工作区结构、System 注册、项目绑定和根目录退役时。</dd>
    </div>
    <div>
      <dt>不定义</dt>
      <dd>单个 Study 的分析目录、代码语言、手稿结构、伦理判断或真实研究材料。</dd>
    </div>
  </dl>
</section>

<section class="component-category-section component-category-relationship" aria-labelledby="framework-relationship-title">
  <div class="component-category-section-heading">
    <p class="map-kicker">RELATIONSHIP</p>
    <h2 id="framework-relationship-title">与其他类别的关系</h2>
  </div>
  <p><strong>Frameworks → Systems：</strong>Framework 提供工作区与绑定概念；每个 System 在该边界内定义其自身的任务路线、生命周期与规则引用。</p>
  <p><strong>Frameworks 与 Skills：</strong>Skill 有独立使用边界；一个 Skill 不因存在于同一工作区或被 System 路线引用而改变 Framework 合同。</p>
</section>
